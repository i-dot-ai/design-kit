This guide is for the technical, accessibility and design reviewers, and the core team who merge and publish. If you're submitting a component, read [contribute to the Design Kit](/get-started/kit-forum) instead.

## Review pull requests

Review within [X working days]. Each of the three reviewers — technical, accessibility and design — approves or requests changes in GitHub, and explains what needs to change and why.

If a contributor cannot do the rework themselves, agree who will and note it on the pull request.

## Merge, publish and announce

When a pull request has all three approvals:

1. Merge it.
2. Release a new version.
3. Check the kit site has updated.
4. Post in #iai-design-kit.

## Look for components worth sharing

Every 2 weeks, check product repos for components built locally. Check them against the component criteria. If one qualifies, open a pull request for it yourself, or ask the team that built it to.

## Pay down kit debt

Every quarter, a named person from design and a named person from frontend spend time on:

- components added below standard
- missing or out-of-date guidance
- changes from GOV.UK Frontend
- promoting experimental components to standard
- deprecations
