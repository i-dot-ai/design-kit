---
title: Contribute to the Design Kit
description: How to contribute to the i.AI Design Kit.
---

Anyone in i.AI can add a component, pattern or improvement to the Design Kit. Make 
sure to search the kit first and use anything that already fits.

>You do not have to wait for a decision. Keep using your version in your
>product while it's reviewed. When the kit version is published, swap yours
>for it.

## Slack channel

[#iai-design-kit](https://i-dot-ai.slack.com/archives/C0C476E1D4H) is the hub for
everything to do with the design kit.

Ideally, we would like people to progress as far as possible with a PR and post in 
slack to where you have got to. It is also good to post initial questions and queries 
about whether to start work or present problems you have found.

## Pull request

Open a pull request against the [design kit repository](https://github.com/i-dot-ai/design-kit)
for a component or updated documentation.

You can stop anywhere. Take it as far as you reasonably can and hand the rest over. 
An incomplete pull request is better than no pull request. All of these are real contributions:

- the docs and examples for a component
- a full component with all its tests
- a variant class on an existing component
- a fix to a component already in the kit
- a decision record

The [contribution guide](https://github.com/i-dot-ai/design-kit/blob/main/CONTRIBUTING.md)
has the technical detail for how to add components, or documentation and what is 
expected for an addition to be accepted. If you are working with AI, point your assistant 
to this contribution guide in order to ensure you are adding to the design kit in 
the expected way.

## Contribute a skill

If your interaction with the design kit is skill led, there may be issues or 
improvements that come from the way a skill interacts with the design kit.

We are trying to improve how skills are shared across the incubator, so if you have 
an improvement suggestion for the prototype and build ones used in this site 
or a personal skill that you believe other people will benefit from, contribute 
it directly to the [skills and projects repo](https://github.com/i-dot-ai/skills-and-projects).

## Review

Three people review your pull request:

- the technical maintainer checks the code can be maintained
- the accessibility reviewer checks accessibility
- a design reviewer checks design quality

They may ask for changes. You can make these yourself, or ask the core team to
take over (which may take longer to publish). When all three approve, the core
team merges, publishes and announces it in Slack. The kit site updates
automatically.

If your contribution isn't accepted, we'll explain why in the pull request. We
keep a record either way.

## Expect it to change

A component built for one product nearly always needs work before it goes in the
kit — removing product-specific bits, adding variants other teams need and
writing guidance. This is normal, not a judgement. Reviewers are there to close
the gap, not catch you out.
